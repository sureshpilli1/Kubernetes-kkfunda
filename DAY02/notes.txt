k8s nameSpaces
==============
In Kubernetes, namespaces are a way to organize and manage resources within a cluster.
They help you divide cluster resources between multiple users or teams and can be useful for managing resource quotas, network policies, and access control.
Here are some key commands and YAML examples related to Kubernetes namespaces:
1. Creating a Namespace
Create a namespace using a YAML file, as shown earlier:

apiVersion: v1
kind: Namespace
metadata:
  name: my-namespace
  labels:
    name: my-namespace

kubectl apply -f namespace.yaml
Alternatively, you can create a namespace directly from the command line:
kubectl create namespace my-namespace

2. Listing Namespaces
kubectl get namespaces  or kubectl get ns

3. Viewing Namespace Details
To get detailed information about a specific namespace:
kubectl describe ns my-namespace

4. Deleting a Namespace
To delete a namespace (along with all the resources within it):
kubectl delete namespace my-namespace

5. Using Namespaces in Resource Definitions
When defining resources (like Pods, Services, Deployments) in YAML files, you specify the namespace under the metadata section:

apiVersion: v1
kind: Pod
metadata:
  name: my-pod
  namespace: my-namespace
spec:
  containers:
  - name: ngnix123
    image: nginx

kubectl apply -f pod.yaml

6. Switching Namespaces in kubectl Context
kubectl config set-context --current --namespace=test

7. Namespace Resource Quotas
You can define resource quotas and limits per namespace to control the usage of resources:

apiVersion: v1
kind: ResourceQuota
metadata:
  name: my-resource-quota
  namespace: test
spec:
  hard:
    pods: "10"

kubectl apply -f quota.yaml




NOTES FROM BLOG:

Namespaces Provides

1. Isolation

• Namespaces keep resources separate so that workloads from different teams or environments don't interfere with each other.

2. Access Control (RBAC)

• You can set Role-Based Access Control (RBAC) policies to restrict access to certain namespaces.
• Only authorized users or teams can view or manage resources in those namespaces.

3. Resource Quotas

• You can set CPU and memory limits for each namespace.
• This stops any single team or application from using up all the cluster’s resources.

4. Environment Segregation

• Namespaces are perfect for keeping different environments apart, such as:
• dev – Development environment
• staging – Testing/pre-production environment
• production – Live environment
• Each environment gets its own namespace, keeping workloads and settings separate.



Types of Namespaces in Kubernetes

1. default

○ Used when you don’t specify any namespace while creating a resource.
○ All resources go here by default.

2. kube-system

○ Contains Kubernetes system components and internal services.
○ Essential for cluster operation — avoid modifying resources here unless necessary.

3. kube-public

○ Stores resources that are accessible to everyone, including unauthenticated users.
○ Commonly used for public information in the cluster.

4. kube-node-lease

○ Manages node lease objects that help in:
▪ Tracking node health
▪ Leader election in the cluster

5. User-defined

○ Custom namespaces created by users for organizing resources by teams, projects, or environments.
○ Helps in keeping workloads isolated and well-managed.

What is swap in Linux?
Swap is disk space used as extra virtual memory when your RAM is full.
Think of it like this:
RAM → fast, expensive, limited
Disk (swap) → slow, cheap, larger
When RAM is exhausted:
Inactive memory pages are moved from RAM → swap
This prevents the system from crashing due to Out Of Memory (OOM)
Why do people disable swap?
Common real-world reasons:
Kubernetes / Docker
Kubernetes requires swap OFF
Swap causes unpredictable scheduling
Performance-sensitive systems

The kernel is the core of Linux.
Kernel settings are runtime parameters that control how the kernel behaves.

Examples:

Memory management

Security features
These settings are exposed via sysctl.
What does “disabling a kernel setting” mean?
It does NOT mean turning off the kernel
It means:
Changing a kernel parameter to stop or restrict a specific behavior

Goal:
Better mileage
Stable driving
No unexpected behavior

What is a Docker GPG key?
A Docker GPG key is a public cryptographic key used to verify that Docker packages are genuine and not tampered with.
In simple terms:
It’s Docker’s official “signature” that proves the software really comes from Docker and hasn’t been modified.
2️.Why does Docker use a GPG key?
When you install Docker from its official repository (APT/YUM):
Packages are signed by Docker
Your system checks the signature
Installation proceeds only if the signature matches
This protects you from:
Fake or malicious packages
Man-in-the-middle attacks
Compromised mirrors
So it’s about security + trust 

This does two things:
Downloads Docker’s public GPG key
Stores it in your system’s trusted keyring
5️.What happens after adding the key?
When you run:
apt update

APT:
Downloads Docker packages
Verifies package signatures using the Docker GPG key
Installs only if verification succeeds
