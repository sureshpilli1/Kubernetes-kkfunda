Network Policies
--> Network Policies in Kubernetes are used to control the communication between pods and   external endpoints. 
--> They are a way to define rules that govern how pods can connect to each other and to other network endpoints. 
--> This can enhance the security of your applications by restricting access and ensuring that only authorized traffic is allowed.

Key Concepts of Network Policies
Namespaces: Network Policies are applied within a specific namespace. You can create different policies for different namespaces.

Selectors: Network Policies use selectors to define the pods they apply to:

Pod Selector: Specifies which pods the policy affects.
Namespace Selector: Specifies which namespaces the policy can affect.

Types of Rules:
	Ingress Rules: Control incoming traffic to the selected pods.
	Egress Rules: Control outgoing traffic from the selected pods.
Policy Types: Each Network Policy can specify rules for ingress, egress, or both.

1. What is a NetworkPolicy?
A NetworkPolicy is:
A Kubernetes resource that controls traffic (ingress/egress) to Pods
Simple idea
Without NetworkPolicy → Everything can talk to everything 
With NetworkPolicy    → Only allowed traffic is permitted

2. Important prerequisite (very important)
NetworkPolicies work only if your CNI supports it
Examples:
Calico ✔
Cilium ✔
Weave ✔
Flannel (basic, no policy support)

3. Types of traffic control
Ingress
Incoming traffic to Pod
Egress
Outgoing traffic from Pod

4. Basic structure
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: example
  namespace: prod
spec:
  podSelector:
    matchLabels:
      app: mongodb

  policyTypes:
  - Ingress
  - Egress

5. Key concept (VERY IMPORTANT)
NetworkPolicy works on:
Pod labels (NOT Services, NOT Deployments)

6. Default behavior
If NO NetworkPolicy exists:
All traffic is allowed 
If NetworkPolicy exists:
Only defined traffic is allowed
Everything else is blocked 

7. Example 1: Allow only Spring app → MongoDB
Goal
Only allow traffic from:
springapp → mongodb
Policy
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: allow-spring-to-mongo
  namespace: prod
spec:
  podSelector:
    matchLabels:
      app: mongodb

  policyTypes:
  - Ingress

  ingress:
  - from:
    - podSelector:
        matchLabels:
          app: springapp
    ports:
    - protocol: TCP
      port: 27017
What this does
Spring Pod → MongoDB Pod → ALLOWED 
Other Pods → MongoDB → BLOCKED

  - Ingress
Meaning:
No Pod can receive traffic
